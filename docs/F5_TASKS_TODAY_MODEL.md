# F5: задачи и экран «Сегодня»

## Аудит существующего поведения

В Android 0.6.2 задачи хранятся внутри зашифрованного `projects[].tasks[]` в
`data.enc`. Каждая строка имеет UUID, `name`, ручные `progress` (0–100),
`status` (`Не начато`, `В работе`, `Приостановлено`, `Завершено`), `done`,
`planDate`, `actualDate`, текстовые `responsible` и `comment`. Редактор
объекта позволяет добавить и удалить задачу; «Сегодня» сейчас считает
просроченные задачи через UTC дату и показывает финансовые сигналы.
`project.estimates[].executionStages[]` F4 и `progressEntries[]` — отдельный
проверяемый журнал фактического объёма работ. Ручной процент задачи его не
заменяет. F1 queue до F5 не проецирует `tasks`, поэтому старые задачи остаются
в исходной зашифрованной базе и резервной копии, но не достигают второго устройства.

Backend Stage 3 уже имеет `tasks` с UUID, tenant/project, assignee, title,
open/in_progress/done, revision, timestamps и tombstone. Его sync push доступен
администратору; до F5 pull/snapshot отдавал все задачи worker внутри организации.

| 0.6.2 / Android | 0.7 local | Sync | PostgreSQL | Экран |
| --- | --- | --- | --- | --- |
| `id`, `project.id` | те же стабильные UUID | `entityId`, `projectId` | `tasks.id`, `project_id` | объект / задача |
| `name`, `comment` | `name`, `comment` | `title`, `description` | `title`, `description` | заголовок / описание |
| `done`, `status` | canonical `taskStatus`, старые поля сохранены | `status` | `status` | открыта / в работе / сделана |
| `planDate` | `planDate` YYYY-MM-DD | `dueDate` | `due_date date` | срок / Сегодня |
| `actualDate` | исходное поле сохранено | `completedAt` только для новых переходов | `completed_at` | дата выполнения |
| `responsible` | старый текст сохранён; `assigneeId` только при явном выборе | `assigneeId` | `assignee_id` | исполнитель |
| `progress` | старый ручной процент сохранён | вне канонической задачи | вне `tasks` | legacy progress |
| нет | `priority` = normal | `priority` | `priority` | normal/high/urgent |
| нет | `estimateId`, `stageId`, `estimateItemId` nullable | те же UUID | FK в контексте объекта | контекст работы |
| нет | `createdBy` только от ответа сервера | не принимает client input | `created_by` из auth | служебно |

Legacy `Приостановлено` остаётся исходным `status`; canonical sync состояние
`open` не стирает его текст или ручной процент. Старую строку с текстовым
`responsible` не назначаем автоматически на одноимённого серверного пользователя.
Удалённые задачи хранят tombstone в change feed; удаление на устройстве
передаётся прежней F1 durable queue. При смене статуса `done` сервер записывает
время завершения, при повторном открытии очищает его. UI не отправляет
произвольный `completedAt` и `createdBy`.

## Права и источники данных

Администратор создаёт, редактирует и удаляет задачи через существующий sync.
Manager читает задачи организации; worker получает только назначенные ему
задачи. На устройстве local auth и server auth независимы: без сети
зашифрованная база открывается по локальным правилам. Менеджер/рабочий не
получают новые права на запись через backend. Конфликты разрешает администратор.
Финансовые данные и сигнал F4 `over_completed` видны только администратору.

«Сегодня» вычисляется из канонических задач и разрешённых сигналов F4;
самостоятельная сущность «today task» не создаётся. Срок сравнивается как
локальная календарная дата, без преобразования в UTC. Задача показывается
ровно в одном блоке: просрочено, сегодня, в работе, ближайшие 7 дней;
задачи без срока видны в блоке «В работе». Приоритет сортирует внутри блока.
Удаление или исправление перерасхода F4 автоматически убирает сигнал.
