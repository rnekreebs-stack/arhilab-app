# Functional 0.7.0, F1 contract

`Project`/`projects` remains the existing internal database and API name; the user sees **Объект**. No `objects` table or migration rename.

In 0.6.2 one object contains exactly one embedded estimate. Old estimates retain their lines, material kits, manual material rows, delivery, discount, costs, photos and unknown fields. Work markup defaults to **0%** and never changes an old result merely by opening it. The proposed 0.7.0 multiple-estimate representation must retain the embedded legacy estimate by a versioned, reversible mapping before a UI can offer multiple estimates per object.

Money policy for new markup: nonnegative decimal values with at most two currency fractional digits, quantities and coefficients at most four fractional digits, half-up to currency cents at each existing line subtotal. `baseWorksTotal = Σ round2(price × qty × coef)` over eligible approved work lines. `workMarkupAmount = round2(baseWorksTotal × workMarkupPercent / 100)`. `worksTotalWithMarkup = baseWorksTotal + workMarkupAmount`. `materialsTotal` is the sum of rounded, priced auto-kit and manual material rows; existing `materialMarkup` (8/10/12%) changes their price independently. `estimateTotal = worksTotalWithMarkup + materialsTotal + delivery − discount`. Markup applies **only** to work, 0–100%, with presets 0/5/10/15/20/25/30. Existing project cost and payment calculations retain their current meaning; do not equate markup to margin. The backend fields and payloads use decimal strings and PostgreSQL NUMERIC, not IEEE-754 money.

Admin/manager may edit the local 0.6.2 estimate; workers do not see it. Server Stage 3 sync writes require authorized admin until a separately reviewed RBAC change. Sensitive local costs remain admin-only. Offline local access and encrypted PhotoStore do not depend on server authentication. Sync conflicts must be surfaced to a user and must not overwrite unsynced local edits. A Stage 3 estimate update with an old revision results in the Stage 4 persisted conflict, not last-write-wins.

The backend's generic `estimate_items` do not yet express 0.6.2 work/material line math. Production Android 0.7.0 sync wiring must only be enabled after a complete, versioned local conversion and server projection with two-device round-trip tests; never use the unencrypted Stage 5 JSON test store for business data on Android.
