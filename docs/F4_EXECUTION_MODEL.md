# F4: фактическое выполнение работ

## Аудит 0.6.2 и граница модели

`project.tasks[]` в 0.6.2 содержит название, вручную заданные `progress`/`status`, даты,
ответственного и комментарий. Это задачи объекта, а не журнал измеренных объёмов конкретной
строки сметы. Их нельзя автоматически превратить в выполненные квадратные метры: нет
связи с `estimateItemId` и исходных отдельных событий. Старые задачи и экран остаются.
`extraStatus` в работе отражает согласование дополнительной работы, а не фактический объём.
Платежи и расходы не означают физического выполнения. Документы «акт этапа» в 0.6.2
печатают задачи; F4 не заменяет и не составляет юридический акт.

| Понятие | 0.6.2 | Android 0.7 | Sync | PostgreSQL |
| --- | --- | --- | --- | --- |
| Этап исполнения | Только несвязанные `project.tasks` | `project.estimates[].executionStages[]` | `stage` | Расширенная `stages`, nullable `estimate_id` для старых строк |
| Текущее назначение работы | Нет | `lines[].stageId` по `syncId` | `estimateItem.stageId` | `estimate_items.stage_id` |
| План работы | `lines[].qty` | То же поле, UUID `syncId` | `estimateItem.quantity` | `estimate_items.quantity numeric(18,4)` |
| Факт выполнения | Ручной процент задачи | `estimate.progressEntries[]`, отдельные UUID | `progressEntry` | `progress_entries` |
| Автор записи | Нет достоверного журнала | ID локального пользователя для отображения | Сервер берёт authenticated user | `progress_entries.created_by` |
| Этап в истории | Нет | `progressEntries[].historicalStageId` в момент создания | Вычисляет сервер при create | `historical_stage_id` |

Существующая зашифрованная `data.enc` и ARHILAB3 backup содержат полные локальные объекты,
поэтому F4-массивы и UUID включаются без отдельного plaintext-хранилища. Миграция локальной
схемы 5→6 только добавляет пустые массивы, не меняет прошлые проценты задач.

## Правила

- Этап относится к одной смете; одинаковая работа в разных сметах имеет разные UUID.
- Одна работа имеет не более одного текущего этапа; `null` означает «Без этапа».
- Запись журнала — положительное *приращение* в дату, до 4 знаков после запятой.
  Дроби суммируются в `BigDecimal` локально и `numeric(18,4)` в PostgreSQL.
- Выполнено = сумма активных записей строки; остаток = план минус выполнено.
  При уменьшении плана отрицательный остаток показывается явно, история сохраняется.
  Новая запись, увеличивающая превышение, отклоняется.
- Процент строки = выполнено / план × 100 при положительном плане.
  Этап и выбранная смета показывают среднее процентов работ с положительным планом,
  каждая работа имеет одинаковый вес. Разные единицы физических объёмов не суммируются.
  Пустой этап имеет статус «Не начат».
- При переносе работы событие оставляет исторический этап; текущая готовность этапа
  рассчитывается по *текущим назначениям*. Цена, наценка, платежи и расходы не влияют.
- Удаление строки при наличии записей журнала блокируется на устройстве и сервере.
  Удаление этапа с назначенными работами блокируется; история этапа остаётся по UUID
  после его tombstone. Журнал исправляется revisioned update/delete, удаление — tombstone.
- Локальный admin ведёт журнал. Серверный `push` сейчас admin-only. Manager и worker
  не получают права записи через F4; worker видит operational feed без цен, скидок,
  наценок, платежей, расходов и private costs. UI не подменяет серверную границу.
- Изменения бизнес-состояния и durable outbox фиксируются одним зашифрованным
  атомарным сохранением. Стабильные UUID и operationId переживают restart и retry;
  отдельные UUID одновременных добавлений не образуют update/update conflict.
  Редактирование одного события или назначения одной строки использует Stage 4 revision conflict.

Из F4 исключены автоматический план по каталогу, сроки, Today, снабжение и акты.
