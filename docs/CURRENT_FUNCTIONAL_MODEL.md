## Compatibility and unresolved integration

The existing backend `project` only accepts `name`; `estimate` only accepts `projectId,name`, and `estimateItem` only accepts `estimateId,title,quantity,unit`. A simple markup column is safe but **cannot** synchronize the current monetary estimate by itself. Local `CloudSync` is not the Stage 3–5 operation queue. Before wiring the production UI to remote sync, a versioned local model and lossless estimate-item/projection mapping must be built and tested (including catalog, coefficients, price, delivery and discount), with atomic encrypted local edits and operation queue writes. Do not replace the existing Android vault or claim that backend object/estimate snapshots reconstruct 0.6.2 data.
